## Phase 0: what the schema refuses

The validator rejects a table that carries two tasks, inconsistent `label_units` inside one
task, a duplicate sequence inside one task, a null `source_doi`, a null `source_table`, a
null `reference_accession`, an absent `label_value`, an assay drawn from another task's
vocabulary, an assay outside the vocabulary entirely, a `sequence_len` that disagrees with
the sequence, a malformed mutation token, a variant with no parent, a parent that is not in
the table, an identifier without its task prefix, and an undeclared extra column.

`safe_concat` and `assert_concatenable` refuse to stack tables whose `task`, `label_units`,
or `label_assay` differ. `test_rejects_merged_two_task_table` proves the forbidden merge is
blocked through the helper, and also proves that a frame merged by hand with plain pandas
still fails validation, so the guard is not only on the convenience function.

Each rejection test perturbs a valid table in exactly one way and asserts that the specific
rule fired. A test that only asserted "something was rejected" would pass even if the
validator rejected the table for the wrong reason.

## Phase 1: four findings that change what Phase 2 does

**The Task B DOI in the brief does not resolve.** The brief gives bioRxiv 2026.07.06.736660,
which reads as prefix `10.1101`. That form returns "no posts found" from the bioRxiv API. The
preprint is real and resolves under prefix `10.64898`: Li H, Wang Y, Zhang C, Thi TT, Shi Y,
Cheng KY, Hu C, Yu H, "Saturated mutagenesis screen of M-MLV reverse transcriptase identifies
variants enhancing prime editing efficiency", posted 2026-07-07, DOI
`10.64898/2026.07.06.736660`. Recording the brief's prefix would have put a non-resolving
citation on 1046 rows.

**A six-residue numbering conflict, which is the pipeline's stated worst failure mode.** The
preprint removes the RNase H domain at "residues L499 to P677", implying a 677-residue RT.
UniProt P03355 sequence version 5 carries the chain "Reverse transcriptase/ribonuclease H
(p80)" at 660 to 1330 of a 1738-residue Gag-Pol, so the canonical RT is 671 residues. Six
residues of offset would shift every variant in both libraries without producing any visible
error. Nine anchor residues are available to settle it: positions 60, 61, 67, 84, 95, 101,
124 must read S, I, S, Q, N, V, D, and the deletion boundaries must read L at 499 and P at
the residue the paper calls 677. The Phase 2 parser asserts all nine and halts on any
mismatch.

**The Task B reference is not wild-type M-MLV RT.** PE2ΔR was built by deleting RNase H from
the RT of pCMV-PE2, Addgene 132775, so it inherits PE2's substitutions. L603W falls inside the
deleted 499 to 677 region, so the reference is most probably a tetramutant truncation carrying
D200N, T306K, W313F, and T330P but not L603W. That is a derivation, not a reading, and it is
to be confirmed against the supplementary protein sequence before any variant is built.

**An arithmetic check on Task B passes.** Stretch 1 runs S60 to Q84, which is 25 positions,
and 25 times 19 non-wild-type substitutions is 475, the stated library size. Stretch 2 runs
N95 to D124, which is 30 positions, and 30 times 19 is 570, the stated library size. Both
libraries are exactly saturating and mutually consistent with the stated boundaries. The
expected count is therefore 1045 variants plus one wild type, and any parsed table shorter
than that has dropped variants which must be logged individually.

## The blocking defect in Task A

No DOI string appears anywhere in the tracked repository outside `legacy_` directories, and
`data/rt_sequences.csv` has no accession column. Every one of the 57 Task A rows therefore
fails the schema on three fields at once: `source_doi`, `source_table`, and
`reference_accession`.

Task A cannot be produced by reformatting the inherited file. Fifty-seven RT names have to be
matched to database entries with versions. The inherited dataset deferred this work rather
than doing it, and the schema is what surfaced that.

Four reconciliation questions are open, all answerable from Supplementary Table S1 of Doman
et al. 2023, `10.1016/j.cell.2023.07.039`:

1. The paper tested 59 enzymes; the inherited table has 57. Which two are absent, and why.
2. The paper reports 20 actives; the inherited table has 21. Either `MMLV-RT` at 41 percent is
   the benchmark control rather than one of the 59, or `Ne144-RT` at 0.5 percent sits below the
   paper's threshold and was called active by a rule applied later. If the second, the binary
   label in this repository is not the paper's binary label and must be labelled as such
   wherever it is used.
3. The paper spans 14 classes; the inherited family column has 7 labels. The coarsening makes
   leave-one-family-out coarser than the source supports. The existing 7 folds are preserved
   for comparability with the audit, and the 14-class mapping is recorded alongside.
4. The inherited table holds one scalar per enzyme. If Figure 1C reports efficiency at more
   than one target locus, that scalar is an aggregate computed by an unknown rule. This is the
   single most important unresolved fact about the Task A label.

One corroboration worth recording: measured locally, actives in the inherited table fall in
exactly 4 of the 7 families, matching the paper's "Twenty RTs from four different classes
showed detectable PE activity". The class structure lines up even though the counts do not.

## Recommendations carried to Gate G1

**PE6: do not join Task A.** They were selected for the label by continuous evolution, so a
PE6 cohort is enriched for actives by construction and would move Task A's base rate for
reasons unrelated to any model. Worse, PE6b and PE6c descend from Tf1 and PE6d through PE6g
from M-MLV RT, and both parents are already Task A rows. Under leave-one-family-out the
descendants land in the same fold as their parents, where they are near-identical to a sequence
already there, so they add redundancy inside folds and lower effective sample size rather than
raising it. The series also runs to PE6g, not PE6d as the brief states. Recommend a separate
transfer cohort, evaluated on but never trained with, if they are wanted at all.

**All three Task C sets: blocked, with reasons.** The retron literature offers roughly four
experimentally validated enzymes, which cannot be split or given a usable interval. No
cross-RT DGR activity panel is established to exist; the quantitative DGR work concentrates on
one enzyme, the BPP-1 bRT. The in vitro retroviral measurements are real but scattered across
decades and laboratories with incompatible quantity definitions, so compiling them into one
column would move the confound from which family to which laboratory, which is the same defect
the task partition exists to prevent.

## What this report does not contain

No activity value, no sequence, no feature, no embedding, no performance number, and no model.
Nothing has been trained and nothing here should be read as a result.

**So Task B has no labels and cannot be built.** That is the honest state, and it is a gap in

### The numbering conflict, closed

Nine anchors, being every residue identity the preprint states, all match P03355 under the
hypothesis that the preprint's RT residue 1 is the first residue of the annotated p80 chain at
Gag-Pol 660: positions 60 S, 61 I, 67 S, 84 Q, 95 N, 101 V, 124 D, 499 L, 677 P.

Two further confirmations arrived independently of the anchors:

- **The preprint's own arithmetic.** Residues 1 to 498 give 1494 base pairs, matching the stated
  "encoded by 1,494bp" exactly; 179 deleted of 677 gives 0.2644, matching the stated "26.4%
  smaller".
- **Generating the Task B variant set from the frame** reproduced 475, 570, and 1045 exactly.

671 against 677 dissolves: both are right about different things. The preprint's RT extends six
residues past the annotated p80 chain to Gag-Pol 1336, into the region UniProt assigns to
integrase, and those residues are `IENSSP`, ending in the P the preprint calls P677.

A fourth, unplanned corroboration came from the inherited data itself: the Task A `MMLV-RT` row
is **677 residues**, the same frame, and differs from P03355 at exactly one position, RT
position 8, which is Y inherited and H in P03355. Two unrelated datasets agree on the 677-residue
frame. That single difference also matters: a reference built from P03355 would be wrong at
position 8 relative to the sequence actually used in the field, which is a further reason the
candidate file is named `reference_candidate_unconfirmed.fasta` and may not be consumed.

Six tests prove the resolver refuses rather than adapts, including a positive control that
deletes six residues ahead of the RT start, which is what a wrong frame actually looks like.

### Still open on the reference

Whether PE2dR retains PE2's RT substitutions. L603 falls inside the deleted region, so it is
most likely a tetramutant truncation carrying D200N, T306K, W313F, T330P and not L603W. That is
a derivation: "pentamutant", "D200N", and "L603W" appear nowhere in the PDF. All four candidate
substitution positions lie outside both diversified stretches, so this does not affect any
variant identity, only the reference's own residues.

### Task A accessions

A resolver was built that identifies each inherited sequence's parent entry by exact substring
containment, using UniProt peptide search to propose candidates and full-sequence containment to
verify them. Validated on three cases: `Tf1-RT` resolves to `Q01910.1` residues 349 to 853,
reviewed, exact. `Ec48-RT` returns no candidate, which is plausible for a retron RT absent from
UniProtKB. The full 57-sequence run is slow because the peptide search service is intermittent.

An accession found this way is a verifiable provenance anchor, not proof of what the authors
used. Supplementary Table S1 remains the authority.

## Phase 3: clustering and splits, done as far as the data allows

Four findings, detailed in `reports/split_design.md`:

1. **No cluster crosses a family boundary at 90, 70, or 50 percent.** Leave-one-family-out
   genuinely prevents identity leakage. This was not guaranteed.
2. **The redundancy is concentrated where the positives are.** At 50 percent, 12 of 18
   retroviral sequences sit in 2 clusters, and the retroviral fold holds 12 of 21 actives. This
   is a sequence-level explanation for the audit's effective sample size of 11.3.
3. **A 90-percent-identical pair carries opposite labels** (`ASLV-RT` active, `RSVSB-RT`
   inactive). No similarity-based method gets both right, and 21 positives cannot say whether
   this is sharp biology or label noise.
4. **Three of seven Task A folds contain no positive at all**, 15 rows between them. Held out,
   each gives an all-negative test set on which a ranking correlation is undefined. Task A's
   leave-one-family-out really rests on 4 folds, one of which has a single member.

Splits frozen: Task A leave-one-family-out (399 rows); Task B position-held-out, stretch-held-out,
and the random split labelled leaky in its filename and in two columns on every row. Task A2 has
no folds because it is evaluation only.

Cross-task clustering cannot run until Task B exists, and is recorded as an open item rather than
a clean result.

## Phase 4: 788 handcrafted features

No scaling, no imputation, no feature selection. Raw values plus a missingness mask; a missing
value is an empty cell, never a zero.

Length 1, amino acid composition 20, dipeptide composition 400, reduced-alphabet tripeptide
frequencies 343, biophysical 12, structural 12.

The k-mer rule is structural rather than statistical, because the brief asks for an a priori rule
and separately forbids feature selection, and any rule picking tripeptides by their frequency in
this dataset would be selection. So the reduction is made in the alphabet: k is 3, 20 residues
reduce to 7 physicochemical groups covering all 20 exactly once, and all 343 features are
emitted. The full 20-letter tripeptide space would have been 8000 columns against 57 rows.

Three structure-to-sequence problems, each handled explicitly rather than silently:

- `Vp96-RT` has no file of that name. `Vp-96.pdb` was confirmed **sequence-identical at all 312
  residues**, so the correspondence is established by sequence rather than by filename
  similarity. This is the same class of name-join defect this repository has been bitten by
  before, and it was caught by checking rather than by assuming.
- `Gs-RT` has a 426-residue model against a 419-residue sequence. Aggregate features only, so
  nothing is misaligned, and `struct_n_residues` makes it visible in the matrix. The accession
  work independently placed the sequence at `E2GM63.1` residues 2 to 420, which is 419 residues,
  consistent with the model being built on a slightly longer construct.
- `Line1-RT` has no structure. All 12 structural columns missing, masked. These are the only
  missing values anywhere in the matrix; 56 of 57 rows are structurally complete.

The confidence feature is named `struct_confidence_mean`, not `plddt`. The brief calls these
AlphaFold models, but their provenance is undocumented here, the files carry a `PARENT N/A`
header, and the global maximum B-factor across all 57 files is 0.99, so the column is a
confidence on a zero to one scale, not a pLDDT on a zero to one hundred scale. Calling it pLDDT
would assert a provenance nobody has established.

## Phase 5: ESM-2 at four scales

16 matrices: 4 scales, 2 layers, 2 pooling strategies, float16 with parallel identifier files.
All 24 manifest artifacts verify, 0 problems.

Layers fixed a priori, final and floor(n/2). No layer sweep: choosing a layer by how it scores is
a selection decision.

The catalytic-core window is `[y - 200, y + 140)` anchored on the first YXDD match, with offsets
derived from M-MLV RT rather than chosen: YXDD begins at residue 222 in the 677-residue frame,
putting the catalytic aspartates at 224 and 225, and the polymerase domain runs to roughly 360.

**The motif is absent in 7 of 57 sequences** (`FuRT-Cas1-RT`, `ROSE-CRISPR-RT`, `CHLRE`,
`Line1-RT`, `Ngaro-RT`, `Ty1B-RT`, `Ec48-RT`). They are excluded rather than pooled over a
guessed window, so catalytic-core matrices have 50 rows, and the verifier checks that 50 plus 7
excluded accounts for all 57.

| model | dim | inference, s | s per sequence | peak RSS, MiB |
| --- | --- | --- | --- | --- |
| 8M | 320 | 4.0 | 0.07 | 491 |
| 35M | 480 | 10.8 | 0.19 | 643 |
| 150M | 640 | 39.0 | 0.68 | 1486 |
| 650M | 1280 | 138.9 | 2.44 | 3405 |

**A finding about the zero-shot scores.** The single-pass log-likelihood improves monotonically
with scale, at -0.4304, -0.3722, -0.3125 per residue for 8M, 35M and 150M, but sitting near -0.3
means roughly 74 percent probability on the residue actually present. That is the signature of
the model reading the token it is scoring rather than predicting it. The files and columns are
therefore named `singlepass`, not pseudo-log-likelihood, and the true masked-marginal quantity is
being computed for the 8M model so the inflation is measured rather than assumed.

## Phase 6: the pipeline report, and a scan that it contains no result

`reports/data_pipeline_report.md`. Every checksum quoted in it was re-verified against the file it
names, and all 16 embedding checksums appear in it. A scan confirms no CLS, correlation, AUC, or
accuracy figure appears anywhere in the document.

Two findings recorded there for the first time:

- **`HIVpol+MMLVRNaseH_RT` is an engineered chimera** of HIV pol and the M-MLV RNase H domain, by
  its own name, which is why no single database entry contains it as a substring. At least one of
  the 57 rows is a construct rather than a member of any RT family, so its family assignment is a
  label of convenience. That matters for a benchmark whose whole framing is cross-family
  transfer.
- 33 of 57 Task A accessions are now resolved and verified by exact substring containment, 18
  from reviewed entries, with zero service errors remaining after two retry passes. So the 24
  that remain are genuine non-matches rather than infrastructure noise. `MMLV-RT` is correctly
  not claimed for `P03355`, because it differs at RT position 8: the tool refuses a near match
  rather than rounding it off.
