## Phase 0: what the schema refuses

The validator rejects a table that carries two tasks, inconsistent `label_units` inside one
task, a duplicate sequence inside one task, a null `source_doi`, a null `source_table`, a
null `reference_accession`, an absent `label_value`, an assay drawn from another task's
vocabulary, an assay outside the vocabulary entirely, a `sequence_len` that disagrees with
the sequence, a malformed mutation token, a variant with no parent, a parent that is not in
the table, an identifier without its task prefix, and an undeclared extra column.

`safe_concat` and `assert_concatenable` refuse to stack tables whose `task`, `label_units`,
or `label_assay` differ. `test_rejects_merged_two_task_table` proves the forbidden merge is
blocked through the helper, and also proves that a frame merged by hand with plain pandas
still fails validation, so the guard is not only on the convenience function.

Each rejection test perturbs a valid table in exactly one way and asserts that the specific
rule fired. A test that only asserted "something was rejected" would pass even if the
validator rejected the table for the wrong reason.

## Phase 1: four findings that change what Phase 2 does

**The Task B DOI in the brief does not resolve.** The brief gives bioRxiv 2026.07.06.736660,
which reads as prefix `10.1101`. That form returns "no posts found" from the bioRxiv API. The
preprint is real and resolves under prefix `10.64898`: Li H, Wang Y, Zhang C, Thi TT, Shi Y,
Cheng KY, Hu C, Yu H, "Saturated mutagenesis screen of M-MLV reverse transcriptase identifies
variants enhancing prime editing efficiency", posted 2026-07-07, DOI
`10.64898/2026.07.06.736660`. Recording the brief's prefix would have put a non-resolving
citation on 1046 rows.

**A six-residue numbering conflict, which is the pipeline's stated worst failure mode.** The
preprint removes the RNase H domain at "residues L499 to P677", implying a 677-residue RT.
UniProt P03355 sequence version 5 carries the chain "Reverse transcriptase/ribonuclease H
(p80)" at 660 to 1330 of a 1738-residue Gag-Pol, so the canonical RT is 671 residues. Six
residues of offset would shift every variant in both libraries without producing any visible
error. Nine anchor residues are available to settle it: positions 60, 61, 67, 84, 95, 101,
124 must read S, I, S, Q, N, V, D, and the deletion boundaries must read L at 499 and P at
the residue the paper calls 677. The Phase 2 parser asserts all nine and halts on any
mismatch.

**The Task B reference is not wild-type M-MLV RT.** PE2ΔR was built by deleting RNase H from
the RT of pCMV-PE2, Addgene 132775, so it inherits PE2's substitutions. L603W falls inside the
deleted 499 to 677 region, so the reference is most probably a tetramutant truncation carrying
D200N, T306K, W313F, and T330P but not L603W. That is a derivation, not a reading, and it is
to be confirmed against the supplementary protein sequence before any variant is built.

**An arithmetic check on Task B passes.** Stretch 1 runs S60 to Q84, which is 25 positions,
and 25 times 19 non-wild-type substitutions is 475, the stated library size. Stretch 2 runs
N95 to D124, which is 30 positions, and 30 times 19 is 570, the stated library size. Both
libraries are exactly saturating and mutually consistent with the stated boundaries. The
expected count is therefore 1045 variants plus one wild type, and any parsed table shorter
than that has dropped variants which must be logged individually.

## The blocking defect in Task A

No DOI string appears anywhere in the tracked repository outside `legacy_` directories, and
`data/rt_sequences.csv` has no accession column. Every one of the 57 Task A rows therefore
fails the schema on three fields at once: `source_doi`, `source_table`, and
`reference_accession`.

Task A cannot be produced by reformatting the inherited file. Fifty-seven RT names have to be
matched to database entries with versions. The inherited dataset deferred this work rather
than doing it, and the schema is what surfaced that.

Four reconciliation questions are open, all answerable from Supplementary Table S1 of Doman
et al. 2023, `10.1016/j.cell.2023.07.039`:

1. The paper tested 59 enzymes; the inherited table has 57. Which two are absent, and why.
2. The paper reports 20 actives; the inherited table has 21. Either `MMLV-RT` at 41 percent is
   the benchmark control rather than one of the 59, or `Ne144-RT` at 0.5 percent sits below the
   paper's threshold and was called active by a rule applied later. If the second, the binary
   label in this repository is not the paper's binary label and must be labelled as such
   wherever it is used.
3. The paper spans 14 classes; the inherited family column has 7 labels. The coarsening makes
   leave-one-family-out coarser than the source supports. The existing 7 folds are preserved
   for comparability with the audit, and the 14-class mapping is recorded alongside.
4. The inherited table holds one scalar per enzyme. If Figure 1C reports efficiency at more
   than one target locus, that scalar is an aggregate computed by an unknown rule. This is the
   single most important unresolved fact about the Task A label.

One corroboration worth recording: measured locally, actives in the inherited table fall in
exactly 4 of the 7 families, matching the paper's "Twenty RTs from four different classes
showed detectable PE activity". The class structure lines up even though the counts do not.

## Recommendations carried to Gate G1

**PE6: do not join Task A.** They were selected for the label by continuous evolution, so a
PE6 cohort is enriched for actives by construction and would move Task A's base rate for
reasons unrelated to any model. Worse, PE6b and PE6c descend from Tf1 and PE6d through PE6g
from M-MLV RT, and both parents are already Task A rows. Under leave-one-family-out the
descendants land in the same fold as their parents, where they are near-identical to a sequence
already there, so they add redundancy inside folds and lower effective sample size rather than
raising it. The series also runs to PE6g, not PE6d as the brief states. Recommend a separate
transfer cohort, evaluated on but never trained with, if they are wanted at all.

**All three Task C sets: blocked, with reasons.** The retron literature offers roughly four
experimentally validated enzymes, which cannot be split or given a usable interval. No
cross-RT DGR activity panel is established to exist; the quantitative DGR work concentrates on
one enzyme, the BPP-1 bRT. The in vitro retroviral measurements are real but scattered across
decades and laboratories with incompatible quantity definitions, so compiling them into one
column would move the confound from which family to which laboratory, which is the same defect
the task partition exists to prevent.
